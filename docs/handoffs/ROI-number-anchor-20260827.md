## 建议下一步

### 1. 先处理当前供应链 checkpoint

不要重跑 ASR、父级翻译、WhisperX 或最终时间轴。当前只需要针对 `S0136` 和 `S0260`：

- 优先尝试人工终稿编辑器修复两页中文，并重新做页面 ID、中文串接和结构校验；
- 如果走代码路径，只重试 `display_page_translation` 失败的页面，绕过旧缓存，不能重新生成整集；
- `S0136` 的目标是补齐两个页面 ID；`S0260` 的目标是把“并不重要”放到所属语义页面。

### 2. 让翻译质量审计与分页门禁解耦

分页失败仍然保持 `BLOCKER`，但不应因此让父级中英文质量审计变成 `SKIPPED`。审计可以直接检查固定 ID 的父级英文和中文，结果只进入审计清单，不修改字幕。这样即使页面生成失败，也能先知道父级翻译有没有问题。

运行审计前明确选择服务。当前配置实际是 OpenCode Go；若要官方 DeepSeek，必须先切换到 DeepSeek 服务，再做定向审计，不能只看模型名 `deepseek-v4-flash`。

### 3. 暂停完整中英字符映射和数字锚点扩展

本轮 4 集、278 页、7 个数字没有发现真实数字错页；数字 `missing` 都是中文数字或单位换算。因此不继续做完整五类语义锚点，也不把数字检查接入生产阻断。

只有当后续出现明确的数字错页样本，或否定/实体错页在多集重复出现，才重新做单类 ROI 测量。

### 4. 优先级判断

当前投入顺序应是：

1. 分页翻译失败局部化和缓存绕过，减少整集 `ERROR`；
2. 分页失败时仍运行父级翻译质量审计，避免质量不可见；
3. 对否定、数字、实体等单类语义锚点分别测量，命中和误报有数据后再决定是否接入；
4. 最后才考虑自动“只切不重排”的页面中文生成。
